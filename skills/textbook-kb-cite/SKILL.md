# 教材知识库 · 写作与引用校验

核心命题只有一个：**交付物里每一句教材内容，都必须能在知识库里找到对应原句，且页码对得上。**
宁可留白，也不要编。用户对「含糊声称依据教材」极其敏感。

## 〇、命令里的 `$PY` / `$ROOT` / 知识库

下文所有命令基于这两个变量，**换机器只改这两行**：

```bash
PY="<你的 python 可执行文件>"       # Windows 上形如 …\envs\<env>\Scripts\python.exe
ROOT="<你的便携包根目录>"           # 解压后任一便携包的根目录
export PATH="/c/Windows/System32:/c/Windows:/usr/bin:/bin:$PATH"                 # Bash 的 PATH 常被清空，须前置
```

`$ROOT` 下固定并排三个目录：`tools/`、`kb/`、`skills/`。
**本技能随分发包发给别人时，对方只需把 `ROOT` 改成自己的解压目录** —— 技能别处没有写死路径。

**每本资料一个便携包**，全部并放在同一个落点目录下（下文示例用 `D:/kb/`）：

```
<落点目录>/
├── <书名>-便携包/{tools,kb,skills}/ …   ← 每本书一个，互不干扰
├── 教材知识库工具包/                     ← 分发包（只有工具链，无原文）
└── *-便携包-YYYYMMDD.zip
```

本机当前已入库哪些书，不在本文件维护 —— 看工程目录的 `.workbuddy/memory/MEMORY.md`。

各包里的 `tools/` 是同一套脚本，用哪个包里的都一样；**决定校验哪本书的是 `--kb`，不是 `$ROOT`**。
所以多本书并存时：`$ROOT` 随便取一个包即可，但命令里必须带 `--kb` 指明用哪本书。

## 一、先定位知识库

**单本可用时首选不传 `--kb`，让脚本自己定位。**
`cite_check.py` 在 `<包>/tools/` 下、知识库在**兄弟目录** `<包>/kb/` 下，相对位置固定，
脚本从自身位置就能推出库在哪 —— 换盘符、换目录都不必改任何配置。

不传 `--kb` 时脚本的判定：

| 情况 | 行为 |
|---|---|
| 恰好一个库 | 直接用它 |
| 一个都没有 | **明确报错**，说明自动定位规则与该传什么 |
| 多库共存 | **报错并列出候选**，绝不静默猜一个（猜错比报错危险） |

**本机 `kb/` 下已有多本书，所以日常一律显式传 `--kb`。** 需要传的路径形如
`$ROOT/kb/<书名>/原文`（`--kb` 也可以直接指向某一章的 .md）。

人工查找顺序（脚本定位失败时按此排查）：

1. **本机固定落点**：`D:/kb/<书名>-便携包/kb/<书名>/`（`$ROOT` 见 §〇）
2. 当前工程的 `.workbuddy/kb/<书名>/`（工作副本，仍有效；Read 试读 `原文索引.md` 确认）
3. 都不在时 Glob 搜 `**/原文索引.md` 兜底（换机器、换盘符时走这步）

**新书入库后**：放到 `kb/<书名>/原文/` 下即可，不必改脚本或配置。

知识库的目录约定：

```
<书名>/
├── 00-使用说明与版本信息.md   ← 先读它：标记约定、书写约定、入库/校验流程
├── 原文索引.md                ← 入口：主题/章/节 → 文件 + 页码（脚本生成）
├── _索引补充.md               ← 库专属附录：条目级细目、待办、交付物登记（可选）
├── _连字修正白名单.txt        ← 连字断裂的逐条修正表（可选）
├── _pages/                    ← 部分页码的页面图片（视觉核对用，可选）
└── 原文/                      ← 【唯一事实来源】逐字原文，勿手工编辑
    ├── _toc.md                ← 完整书签 + 页码映射
    ├── _extract_report.md     ← 抽取体检报告（书名、页数、偏移、置信度都从这里读）
    └── NN-章名.md             ← 每页内嵌 <!-- pdf=42 book=21 --> 锚点
```

`book` = 书内印刷页码；反推原 PDF 物理页 = `book + 页码偏移`（偏移量见该书 `00-使用说明与版本信息.md`
的「来源登记」，**绑定这一份 PDF**，实测各书不同：皮肤性病学 21、妇产科学 23、精神病学 17、神经病学 25）。

找不到知识库时：直接告诉用户没找到，并列出你搜过的路径 —— 不要转而按训练记忆编写。

## 二、写作流程（四步，缺一不可）

1. **定位**：读 `原文索引.md`，找到目标章 → 文件 + 页码。
2. **取原文**：读 `原文/NN-章名.md`，用**短关键词**检索再按锚点读上下文
   （正文保留 PDF 原始换行，页眉图注混在文中，跨页处会被版面元素打断，直接搜长句必失败）。
3. **写作**：基本照抄原句措辞，标注 `p.xx`。允许的改写只有排版层面。
4. **校验**（红线）：

```bash
# PY / ROOT 见 §〇；多本书并存时必须传 --kb
"$PY" -X utf8 "$ROOT/tools/cite_check.py" "交付物.html" --kb "$ROOT/kb/妇产科学-第10版/原文"
# 产物：<交付物名>-引用校验报告.md（写到交付物同目录）

# 也可直接指向某一章
"$PY" -X utf8 "$ROOT/tools/cite_check.py" "交付物.html" \
      --kb "$ROOT/kb/妇产科学-第10版/原文/18-外阴及阴道炎.md"
```

脚本路径写完整，别依赖当前工作目录。
`cite_check.py` **只用标准库**，Python ≥3.9 即可。

**`--kb` 与 `--chapter` 的分工**：

| 参数 | 作用 |
|---|---|
| `--kb <原文目录>` | 用哪本书（多本并存时必传） |
| `--kb <某一章的.md>` | 同上，且只校验该章 |
| `--chapter 18` | 只加载第 18 章当语料，判定更严格 |
| 都不传 | 加载**整库**：跨章交付物不必逐章切换 |

整库模式的已知代价：别章的巧合字面串可能把本页已有支撑的内容判成「异地」，
书末的中英文名词对照索引也可能先被命中而成为「教材实际位于」的证据页。
报告里出现可疑「异地」时，用 `--chapter` 复跑单章模式核对。

**不要给脚本加任何默认的绝对路径** —— 那等于把知识库位置写死在脚本里，换机器即失效；
按「脚本自身位置」推断才是可迁移的做法（跨机器跨目录能用的原因就在这）。

## 三、报告怎么读

| 判定 | 含义 | 处理 |
|---|---|---|
| `无出处` | 整句教材找不到 | **必改** |
| `含未见片段` | 句子有原文打底，但夹带了教材没有的话 | **必改**，报告会点出具体片段 |
| `异地` | 教材有，但页码标错 | 改页码 |
| `改写·接近` / `改写·部分` | 措辞有出入 | 人眼确认 |
| `重组` | 信息元都在，只是顺序不同 | 通过 |
| `原文` | 字面命中 | 通过 |
| `声明留白` | 交付物明写「教材未述」 | 通过 |
| `归纳` | 层次描述、辨析、页脚等说明性文字 | 通过（本就允许非原文） |

**报告里出现「无出处」或「含未见片段」= 不得交付。** 这不是建议，是硬红线。

**`含未见片段` 是最有价值的一档**：专抓「真话里夹假话」。
如「…**滴虫阴道炎的复发率为 30%～50%**」—— 前半句有原文对应，
整体覆盖率会因此被抬高，只看覆盖率就会放过。工具用滑动窗口做最长连续命中，
把没有原文支撑的片段单独列出来。

**它只抓字面，不判语义。** 它是「交付物有没有偏离原文」的尺子，
**不是「知识是否正确」的裁判**，结论里必须这样交代。

## 四、动过 cite_check 后必须自检

```bash
"$PY" -X utf8 "$ROOT/tools/cite_check_selftest.py" "交付物.html" --kb "$ROOT/kb/皮肤性病学-第10版/原文"
```

五步全过才算正常：
- **第 0 步 · 环境健壮性**：跨盘符（交付物在 C:、知识库在 D:）时报告仍能生成
- **第 0b 步 · 知识库定位**：`kb/` 下单本可定位、多本不猜、空包不指定、缺 `原文/` 不算候选
- **第 0c 步 · 零单元守卫**：结构不匹配时必须**报错退出**，不得给出一份假的「通过」
- **第 1 步 · 基线干净**：未植入错误时零「需处理」
- **第 2 步 · 植入检出**：3 项**历史上真犯过的**错（编造限定、编造英文名、页码标错）逐条检出。
  **锚点是绑定某本书内容的**（写在 `PLANTS` 里，目前是皮肤性病学）：换书后基底交付物不含锚点时
  会整步跳过，此时脚本判「检出能力**未验证**」并以 exit 1 退出 —— 跑完一遍不等于测过。
  用另一本书的交付物作基底时，若要看检出能力，需先按该书的原文改写 `PLANTS`。

任一漏报即判定校验器退化（exit 1）。
**一个"看什么都报通过"的校验器比没有更危险** —— 它给人虚假的安全感。

**交付物必须符合校验器的结构约定**（`row`/`cell`/`name`/`pg`、`sx`/`sxh`/`v`、
`ov-grid`、`disc-grid`、`layer`、`foot` 等）。它不是通用 HTML 提取器：
普通 `<h1>/<p>` 页面会抽出 0 个单元。这类情况现在会**直接报错退出**，
因为「查过都没问题」和「根本没查」绝不能长得一样。冒烟测试用最小结构即可：

```html
<div class="row"><span class="pg">p.21</span>
  <div class="cell">照抄被引资料的一句，并标了来源页码</div>
  <div class="cell">这句是编的：所有条目都会在三天内自行消失</div></div>
```

### 四之二、结构约定的四个实操坑（2026-09-21 实测，精神病学第八章）

第一版交付物跑出「无出处 9 + 含未见片段 3 + 异地 15」，全部由下列四条引起，不是内容错：

1. **`name` 列只放教材原词。** 拉丁字母 `span` 会被当作「英文名」独立校验（写 `core`/`psych`
   这类装饰标签 ⇒ 15 条「异地」）；自拟短语（「分型一」「续」「归纳自教材小标题」）会被拼进
   中文名一起查 ⇒ 判「无出处」或「含未见片段」。装饰标记改放 `cell` 内的 `span.note`。
2. **编辑性/导读性整句不要直接写进 `cell`。** `grid` 恒为硬性，一句自己的话就是一条「无出处」。
   放进 `span.note` 或 `foot`（均为软性，判「归纳」）。
3. **页码按页断行。** 整句横跨页边界时，两页都搜不到连续串（页面之间夹着页眉与印刷页码）。
   按页拆成两行；续行的 `name` 写「（续）」—— 归一化后 3 字，低于 4 字下限会被跳过，不误报。
   同理，`name` 若与所在行不同页（如小标题印在前一页）会判「异地」，续行别复用原标题名。
4. **核对页码归属要按 `<!-- pdf=… book=… -->` 逐位核对**，不要凭「小标题在哪页」推断。
   本次把 p.103 的整段误标成 p.102，就是没看锚点只看目录印象。

判读提醒：`归纳` 档里出现的 `span.pg` 页码、`foot` 说明、`note` 都是软性内容，属预期；
但**别把实质教材陈述放进这些位置**——那样等于绕过校验。

## 五、写作硬约定（用户已定，不得违反）

- **别名用 `/`**：教材「也称/又称/亦称/又叫/简称」引出的等价名，写 `主名/别名`
  （如 `阴道毛滴虫病/滴虫阴道炎 trichomonal vaginitis，TV`），主名取教材条目名。
  判断口径：**两边互换后含义是否完全不变**。
  大小档、派生类型**不得**用 `/`。
- **并列项用顿号**：教材条目名原文用「和」的，交付物改写为顿号。
- **教材未述一律留白**，用灰字标注「教材未述」，**绝不补写**。
- **分层/分类若属模型归纳，必须显式标注为归纳**，不得冒用教材口吻。
- 不得声称「100% 依据教材」，除非逐条对照过原文并标注了页码。

## 六、知识库自身的维护

```bash
KB="$ROOT/kb/妇产科学-第10版"          # 换书只改这一行；PY / ROOT 见 §〇

# 重建索引（改了原文或 _索引补充.md 就要重跑）
#   索引头部读自 原文/_extract_report.md 与 _toc.md，不写死任何一本书的信息；
#   库专属内容（细目、待办、交付物登记）写在 $KB/_索引补充.md，重建时原样追加。
#   $KB/原文索引.md 是脚本产物，直接改会被下次重建覆盖。
"$PY" -X utf8 "$ROOT/tools/kb_index.py" --kb "$KB"

# 新书入库：先诊断（不落盘），确认结论再抽取
#   ⚠ 判读规则见包根《新书入库核对清单.md》——
#     重点看：页码偏移置信度、切章是否退回「25 页机械切块」、连字可疑清单逐条人工判
"$PY" -X utf8 "$ROOT/tools/pdf2kb.py" probe "新书.pdf"
#   新书放到 kb/<新书名>/原文/ —— 与已有各书平级，不要混进同一本
"$PY" -X utf8 "$ROOT/tools/pdf2kb.py" extract "新书.pdf" --out "$ROOT/kb/新书名/原文" --tidy
"$PY" -X utf8 "$ROOT/tools/kb_index.py" --kb "$ROOT/kb/新书名"

# 若 probe 报「内置书签 0 条」：不能按书签切章，要做一份章节清单再用 --chapters 抽取，
#   否则会退回「每 25 页机械切块」。清单格式与做法见 §七.6。
"$PY" -X utf8 "$ROOT/tools/pdf2kb.py" probe "新书.pdf" \
      --chapters "$ROOT/kb/新书名/_章节目录.txt"
"$PY" -X utf8 "$ROOT/tools/pdf2kb.py" extract "新书.pdf" \
      --out "$ROOT/kb/新书名/原文" --tidy --chapters "$ROOT/kb/新书名/_章节目录.txt"

# 重新打包并同步到落点（改过 kb/ 或 tools/ 后都要跑，否则三处副本会漂移）
#   不要另外传 --out 指向落点：zip 就地写入落点、再由 --deploy 解包，
#   会变成对自己复制（SameFileError）。用默认输出位置最省事。
"$PY" -X utf8 "$ROOT/tools/make_portable.py" --kb "$KB" --deploy "D:/kb"

# 分发包：不含任何教材原文，用于发给别人 / 上传公开仓库
"$PY" -X utf8 "$ROOT/tools/make_portable.py" --dist
#   → 教材知识库工具包-YYYYMMDD.zip（约 70KB）
#     内容：tools/ + skills/ + demo/ + README.md + 新书入库核对清单.md + LICENSE + .gitignore + 空的 kb/ 说明
#     demo/ 是自带示例（自编文字、无版权）：新人不必先入库一本书，就能跑通一次校验看到结果
#   → 上传 GitHub 的完整步骤见 tools/dist-assets/上传GitHub步骤.md
#     分发前自动脱敏：文本里的 `C:/Users/<用户名>/…` 会换成 `<用户目录>`，
#     打包输出末尾列出替换清单 —— 一旦报出文件名，就说明有本机路径混进来了
#   → 改过 tools/ 后，落点 D:/kb/教材知识库工具包/ 也要用新 zip 解压覆盖，否则两边漂移
```

`pdf2kb.py` 需要 `pymupdf`；`html2pdf.py` 需要本机 Edge/Chrome。其余脚本零依赖。
`原文/` 是脚本产物，**不要手工编辑** —— 重跑会被覆盖，且破坏"逐字保真"的可验证性。

**分发包不含任何教材原文**（教材正文是受版权保护的出版物内容，公开分发即侵权）。
核验排除规则时注意：`git ls-files` 默认给中文路径加引号输出，
必须用 `git -c core.quotePath=false ls-files | grep '^kb/'`，
否则一行都匹配不到 —— **假阴性：看着干净、实际已纳入**。

**删掉工作区文件 ≠ 清除。只要 `git add` 过并 commit 过，内容就留在 git 历史里，随 push 一起公开。**
发布前要查的是**历史**，不是工作区：

```bash
git rev-list --all --objects | grep <文件名>        # 这个文件进过任何一次提交吗
git grep -n -I -e <敏感串> $(git rev-list --all)    # 历史内容里搜本机路径 / 账号 / wxid
```

已经推上去的，`push --force` 只让旧提交变成「不可达」—— 按 SHA 直链短期内仍可能打开，
要等 GitHub 自行回收（时间不定），而且仓库一旦被 fork，fork 里照样留着。
**仓库刚建、无 fork 时，直接删库重建、只推一条干净历史，是最彻底也最快的办法**
（重建后记得先清本机的旧压缩包，那些包里往往还带着同一个文件）。

**同一份知识库存在三处副本**：固定落点主副本（`D:\kb\<书名>-便携包\`）、装包 zip、
工程目录下的 `.workbuddy/kb/` 工作副本。改过 `kb/` 或 `tools/` 后**跑一次
`make_portable.py --kb <库> --deploy D:/kb`** 即可三处对齐；不做同步的话，
校验用的到底是哪一版就说不清了。逐文件核对用 `verify_copies.py` —— 它**不随包分发**，
只在开发工程目录的 `tools/dist-assets/` 下：

```bash
"$PY" -X utf8 "<工程目录>/tools/dist-assets/verify_copies.py" --kb-name <书名> --dest D:/kb
```

（脚本只覆盖同名文件、不删除目录：zip 是完整快照，且删除式同步会误伤落点里后放的东西。）

**同步别用 shell 的 `unzip`。** Git Bash 下它处理不了中文路径：会在落点下另建一个乱码目录，
目标目录完全没更新，而命令输出看起来是成功的（又一处「看着通过、其实没做」）。
要解压就交给 Python，或者干脆只用 `make_portable.py --deploy`。

**分发包会悄悄落后于本机技能。** 改过 `skills/` 后，`教材知识库工具包-<日期>.zip` 与
`D:\kb\教材知识库工具包\` 都要重打重同步，否则 `verify_copies.py` 会在每本书上都报同一处
`SKILL.md` 不一致 —— 那不是四本书各自的毛病，是一处分发件没跟上。

**跨盘符是常态**（交付物在 C:、知识库在 D:）。`os.path.relpath` 在 Windows 上对跨盘路径抛
`ValueError`，且**只在报告生成阶段爆** —— 控制台摘要照常打印、退出码正常，表现是「静默丢报告」。
报告里一律走 `rel_or_abs()`；排查「报告没生成」时优先怀疑这里。

**迁移是否成功，必须在新落点实跑完整自检才算数；「本地全绿」≠「目标环境可用」**——
2026-09-20 本地解压测试全过，搬到 D: 第一次跑就崩。
迁移时要一并交代：① 页码偏移绑定这份 PDF，换 PDF 即作废；② 书写约定记在项目 memory 里，不在包内。

## 七、加新书时最容易踩的坑（2026-09-21 实测）

把一本书上的假设带到下一本，会出静默错误。加新书前先确认这几处没有写死：

1. **页码偏移必须重推**，不能沿用（实测各书 21 / 23 / 17 / 25 不等）。
2. **书签层级不一定相同**：皮肤性病学的「第X章」在书签第 2 级，妇产科学与神经病学在第 1 级，
   精神病学**一条书签都没有**。`probe` 会按「哪一级「第X章」条目最多」自动选，切完要核对章节数对不对。
3. **连字候选要逐条人工判**，别整套照搬另一本的白名单。
   妇产科学的唯一候选 `of labor`×10、精神病学的 3 种 5 处（`of love`/`of ideas`/`of learning`）
   都是正常英文短语（`mechanism of labor`、`theory of love`），属误报，不入白名单。
4. **`probe` 报的「页码不一致页」多是误报**：它只扫页尾，页码排在该页页首时就扫不到；
   前置材料（版权页、序言、目录）本就**不印页码**，也会被列进去。神经病学那本报了 20 处，逐类查完
   全是这两类误报。**想真正确认映射，用下面这个全量复核，别只看置信度** ——

   ```python
   # 逐页取文字，看「该书内页码」是否作为【独立一行】出现
   import pymupdf
   d = pymupdf.open("整本教材.pdf")
   bad = [(i + 1, i + 1 - 偏移) for i in range(偏移, d.page_count)
          if str(i + 1 - 偏移) not in [l.strip() for l in d[i].get_text().splitlines() if l.strip()]]
   print(len(bad), bad)   # 神经病学：425 页只 2 页未命中，且都是封底无文字
   ```

   命中率高说明公式对、印刷页码也确实抽得出来（将来 `cite_check` 判「异地」才有意义）。
5. **库专属内容不要写进脚本**：索引的头部与库专属附录、校验器的默认章号、索引里按书签
   **层级**数章数（无书签的书全是 1 级，会把章数算成 0），都曾是「为第一本书量身定做」的
   写死点。发现一处就改一处，别让新书替旧书背书。
6. **书可能根本没有书签（实测第 3 本就是 0 条书签）**。此时 `probe` 会提示、`extract` 会退回
   「每 25 页机械切块」—— 那样切出的文件对溯源没有用，**不要就这么抽完交差**。
   正确做法是给一本**章节清单**，交 `--chapters`：

   ```
   # 文件放 <库>/_章节目录.txt，每行「起始书内页<TAB>标题」，# 开头为注释
   1	第一章 绪论
   10	第二章 精神障碍的症状学
   330	@后置材料（推荐阅读与中英文名词对照索引）     ← @ 开头 = 正文后的独立片段，文件名前缀 99
   ```

   清单从**印刷目录页**抄（目录页上「第X章 / 章名 / 起始页码」是三行一组），抄完必须核两遍：
   ① 逐条对照目录页；② 抽查各章 PDF 首页是不是该章开头（可批量打印每章首页首行来对）。
   切章结果与有书签的书完全一致，`_toc.md` 照常生成。**清单进知识库留档**，它是切章依据，
   不是临时文件；改清单等于改章边界，改完要重跑 `extract` + `kb_index` 并重新抽查章首页。

   **清单首行不要写前置材料**（如 `@前置材料 1`）：`extract` 会自动把封面到第一个章起始页之前
   写成 `00-前置材料.md`，手写一条 `@前置材料` 反而会把「第一篇」扉页误切出去。

7. **章号可能在篇内重号（实测第 6 本耳鼻喉）**：九个篇，每篇都从「第一章」起。用教材章号做
   文件名（`NN-章名.md`）会让九个「第一章」互相覆盖。改法：标题写成「篇名·章名」，
   `extract` 对匹配不到 `第X章` 的标题会退化为全书连续编号（`02-总论·绪论.md` …），文件名不重号。
   **副作用**：`kb_index.py` 按 `第X章` 正则判章，「篇名·章名」匹配不到，索引头部会显示
   「章 0 / 其他 89」——**只是统计口径，不影响检索/引用/页码**，在 `_索引补充.md` 里说明即可，
   不要为这一本书去改 `kb_index.py` 的判章正则（会破坏其他书的通用判定）。
