# 教材知识库工具包

把带文字层的 PDF 转成带页码锚点的 Markdown，再把交付物中每一条事实陈述回查原文，
输出逐句引用校验报告。用于「严格依据某本资料写作」时的交付前自检。

不限于某一学科。教材、国家标准、行业规范、法规、技术手册都可以入库，只要 PDF 自带文字层；
校验依据是「与被引原文是否一致」，与学科无关。

本包只含工具链，不含任何书籍正文，原因见 [§10](#10-版权与许可)。

## 1. 功能

- **资料入库** `tools/pdf2kb.py` —— 四项诊断（文字层 / 页码偏移 / 切章方案 / 连字断裂），
  通过后抽取为逐章 Markdown，每页内嵌 `<!-- pdf=42 book=21 -->` 锚点，实现逐页溯源
- **引用校验** `tools/cite_check.py` —— 抽出交付物中每条事实陈述，回查原文对应页，
  输出九档判定与一份 Markdown 报告，必须处理项计入「需处理」
- **空抽取防护** —— 交付物结构不符约定、抽不到内容单元时直接报错退出，不输出「通过」报告
- **能力自检** `tools/cite_check_selftest.py` —— 植入三类历史上真实发生过的错误，
  验证校验器仍能逐条检出
- **索引重建** `tools/kb_index.py` —— 生成「原文索引.md」（主题 / 章 / 节 → 文件 + 页码）
- **交付物导出** `tools/html2pdf.py` —— 调用本机 Edge 或 Chrome 打印为 PDF（可选）
- **AI 技能（可选）** —— 安装后，AI 自动执行「读原文 → 写作时标页码 → 跑校验」全流程

校验链（查原文 / 写作 / 跑校验）只用 Python 标准库，仅入库需要第三方依赖。

### 1.1 校验哪些偏差

```
结节为实质性、深在性、可触诊的皮损，直径一般大于 1cm。
```

前半句是教材原文，后半句不是。这类句子与原文重合度可达七成，逐字核对时容易放过。
校验器改用滑动窗口取最长连续命中，把没有原文支撑的片段单独标出，判为「含未见片段」。

### 1.2 边界

只比对字面，不做语义判断。用词都能在原文中找到、但结论被改写的句子可能落在「改写」档
而非必须处理项，需人工确认。它衡量的是「交付物是否偏离原文」，不是「内容本身是否正确」。

| `kb_index.py` | 仅标准库 | 修改原文后 |

## 3. 快速开始

### 3.1 放置

解压到长期不变的位置，例如 `D:\教材知识库\`。

脚本与知识库是兄弟目录（`tools/` 与 `kb/`），`cite_check.py` 由自身位置推断库的位置。
因此不需要配置任何路径，也不必传 `--kb`；换盘符、换目录同样有效。

### 3.2 入库一本资料

先诊断，`probe` 只读、不产生任何文件：

```bash
python tools/pdf2kb.py probe "D:/书/你的资料.pdf"
```

按顺序核对四行输出。

**① 文字层**

```text
判定：含有效文字层，可直接抽取原文（零 OCR 误差）
```

出现此行即可继续。平均每页一千余字符属正常；只有几十字符或显示「无文字层」则为扫描版，
本工具不含 OCR，需先用其他工具转成带文字层的 PDF。

**② 页码偏移**（决定后续全部页码）

```text
页码映射：书内页码 = 物理页 − 21　｜　置信度 91%
```

含义是：这份 PDF 的第 42 个物理页，印在书上是第 21 页。偏移量绑定这一份 PDF，
换印次、换版本即作废。

| 置信度 | 处理 |
|---|---|
| ≥ 85% | 可继续，仍须扫一眼「不一致的页」列表 |
| 60–85% | 必须人工抽查：任选 3 个正文页，与 PDF 肉眼比对 |
| < 60% | 停手，该映射不可信 |

「不一致的页」若只含封面、版权页、目录、序言等前置页，属正常；夹有正文页码则须查明原因。
此处判错会让全书页码系统性偏移，而校验报告不会显示这一点。

**③ 切章方案**

```text
切章方案：按书签第 2 级（共 29 章）
```

按书签切章是最佳情况。另外两种情况都应停手处理，不要在错误边界上继续抽取：

- `⚠ 未识别出章级目录，将退回按 25 页机械切块` —— 书签里没有「第X章」条目
- `内置书签目录：0 条  ⚠ 无目录` —— 这份 PDF 根本没有书签

两种情况都能靠**章节清单**解决：从**印刷目录页**把「章起始页 + 章名」抄成一份文本
（目录页上「第X章 / 章名 / 起始页码」通常三行一组），每行 `起始书内页<TAB>标题`，
`#` 开头为注释，用 `--chapters` 传进去：

```text
# kb/你的书名/_章节目录.txt
1	第一章 绪论
10	第二章 精神障碍的症状学
330	@后置材料（推荐阅读与中英文名词对照索引）    ← @ 开头 = 正文后的独立片段
```

```bash
python tools/pdf2kb.py probe   "D:/书/你的资料.pdf" --chapters "kb/你的书名/_章节目录.txt"
python tools/pdf2kb.py extract "D:/书/你的资料.pdf" --out "kb/你的书名/原文" --tidy \
    --chapters "kb/你的书名/_章节目录.txt"
```

清单要核两遍：逐条对照目录页，再抽查各章 PDF 首页是不是该章开头。
清单放在知识库里留档 —— 它同时是切章依据，不是临时文件。

**④ 连字断裂**

```text
连字断裂可疑（如 `f issure`）：29 种 / 75 处
          示例：`f ibers`×8、`immunof luorescence`×4
```

这是**可疑清单而非错误清单**，须逐条判断：`f issure` 是抽取时把 fissure 拆断，应修；
`of lesions`、`of interest` 是正常词界，不能修。判不准就不要写入白名单。

四项通过后执行抽取与建索引：

```bash
# 抽取。--out 是输出目录，与 cite_check 的 --kb（输入）不是同一个参数
python tools/pdf2kb.py extract "D:/书/你的资料.pdf" --out "kb/你的书名/原文" --tidy

# 有连字白名单时追加
python tools/pdf2kb.py extract "D:/书/你的资料.pdf" --out "kb/你的书名/原文" --tidy \
    --ligature-fixes "kb/你的书名/_连字修正白名单.txt"

# 重建索引，生成「原文索引.md」
python tools/kb_index.py --kb "kb/你的书名"
```

`--out` 必须落在 `kb/<书名>/原文`，自动定位依赖这个结构。

> [!NOTE]
> `--strip-running-head` 默认关闭，建议保持关闭：章的起始页常以「第四章 XXX」占据页眉位置，
> 剥离页眉会连同章标题一起删除。确需使用时，事后必须核对章标题是否还在。

诊断数字的完整判读范围与停手条件见 [`新书入库核对清单.md`](新书入库核对清单.md)。

### 3.3 首次校验

按 [§4](#4-交付物结构约定) 的结构写一份最小交付物 `试跑.html`：一行照抄教材原句，
一行写入教材中没有的内容。然后运行：

```bash
python tools/cite_check.py 试跑.html
```

预期结果：照抄的一行判「原文」，自编的一行判「无出处」。前者说明环境与路径正确，
后者说明校验器在正常工作。报告输出到交付物同目录（`试跑-引用校验报告.md`），
开头的「事实来源」应指向 `kb/你的书名/原文`。

### 3.4 工具自检

```bash
python tools/cite_check_selftest.py 试跑.html
```

依次验证五件事：

| 步骤 | 验证内容 |
|---|---|
| 第 0 步 · 环境健壮性 | 交付物与知识库跨盘符时，报告仍能生成 |
| 第 0b 步 · 知识库定位 | 单本可定位、多本不猜测、空包不指定 |
| 第 0c 步 · 零单元守卫 | 结构不匹配时报错退出，而非输出「通过」 |
| 第 1 步 · 基线 | 作为基底的交付物本身没有必须处理项 |
| 第 2 步 · 检出能力 | 植入三类历史真实错误，要求逐条检出 |

> [!IMPORTANT]
> 第 2 步的植入锚点写在 `cite_check_selftest.py` 的 `PLANTS` 中，针对《皮肤性病学》第 10 版。
> 基底交付物不含这些锚点时该步会被跳过，脚本判定「检出能力未验证」并以非 0 退出 ——
> 换书使用时须按新教材改写锚点，并用该书的交付物作基底。

末行出现 `结果：检出 3/3` 与「校验器工作正常」，即工具正常。

### 3.5 安装 AI 技能（可选）

把 `skills/textbook-kb-cite/` 整个目录复制到：

- Windows：`C:\Users\<用户名>\.workbuddy\skills\`
- macOS / Linux：`~/.workbuddy/skills/`

之后提到「按教材写」「教材原文」「引用校验」时，AI 会自动执行本流程，无需重述约定。
技能内部路径写法为「自动定位优先、显式路径兜底」。

## 4. 交付物结构约定

校验器按 class 识别内容，不是通用 HTML 文本提取器 —— 只有认得出结构，才能区分
正文、页码标记与旁注。最小可用结构：

```html
<div class="row">
  <span class="pg">p.21</span>
  <div class="name">斑疹</div>
  <div class="cell">皮肤黏膜的局限性颜色改变，直径 ≤1cm</div>
  <div class="cell">这句是编的：所有皮损都会在三天内自行消退</div>
</div>
```

| class | 放置内容 | 是否校验 |
|---|---|---|
| `row` | 一行 | 容器，不校验 |
| `pg` | 页码标记，如 `<span class="pg">p.21</span>` | 不校验，决定该行页码 |
| `cell` | 行内正文格 | 校验，须有原文支撑 |
| `name` | 名称列（术语名、条目名） | 校验；其中外文名单独校验 |
| `sub` / `sub-grid` | 子表格（分型、分级等） | 校验 |
| `sx` / `sxh` / `v` | 条目卡容器 / 标题 / 内容 | 校验 |
| `ov-grid` | 总览区 | 校验 |
| `note` | 内嵌旁注 | 软性，无出处不算错 |
| `na` | 「教材未述」留白标记 | 软性，找不到才是对的 |
| `disc-grid` | 辨析区（内容来自多页） | 软性，不锁页码 |
| `layer` / `foot` / `gnote` / `ghead` / `schead` | 层次带 / 页脚 / 分组说明 / 分组标题 / 节标题 | 软性 |

示例句取自一本皮肤科教材。换成法学、工程、金融等资料时，class 与用法完全一致 ——
区分的始终是「正文 / 页码标记 / 旁注」三种来源，与被引资料属于哪个学科无关。

两类位置的区别是实质性的。软性位置（旁注、页脚、分组标题）允许是编者自己的话，
不会因教材中没有而被判错；其余位置要求字面有原文支撑，找不到即报出。
另有一条例外：文字中自称「教材原文 / 教材明言」或标注了 `p.xx` 的，无论位于何处一律严格校验。

> [!WARNING]
> 交付物若为普通 HTML（`<h1>`/`<p>` 不带上述 class），校验器会抽出 0 个内容单元并直接
> 报错退出，不会输出一份写着「未检出教材未见的内容」的报告 —— 未经校验时不会给出通过结论。

## 5. 校验报告判读

每条子句归入九档之一，按处理方式分三类。

**必须处理** —— 摘要中「需处理 N 条」即以下三类之和

| 判定 | 含义 |
|---|---|
| ✗ 无出处 | 整句在所引原文中找不到，且未声明为归纳 |
| ✗ 含未见片段 | 句子有原文作底，但夹入了原文没有的内容 |
| ⚠ 异地 | 内容出自原文，页码标错；修正页码即可 |

**需人工确认**

| 判定 | 含义 |
|---|---|
| ⚠ 改写·接近 | 措辞略有出入，大概率等价 |
| ⚠ 改写·部分 | 重合度偏低，可能是转述，也可能是混写 |

**通过**

| 判定 | 含义 |
|---|---|
| ✓ 原文 | 字面命中所引资料的该页 |
| ◇ 重组 | 每个信息元都在原文中，只是排列不同 |
| ◇ 声明留白 | 交付物明说「教材未述」，找不到正合预期 |
| ◇ 归纳 | 声明为归纳或位于说明区，无出处属预期 |

摘要末行为「✓ 未检出『教材未见』的内容」时，前三类中的必须处理项为零。

```bash
python tools/cite_check.py 交付物.html --verbose          # 展开「原文」级明细
python tools/cite_check.py 交付物.html --json 结果.json   # 另存机器可读结果
python tools/cite_check.py 交付物.html --chapter 21       # 换章，默认 04
```

交付前唯一的门槛：报告中出现「无出处」或「含未见片段」，不要交付。

## 6. 命令行参考

### cite_check.py

```text
usage: cite_check.py [-h] [--kb KB] [--chapter CHAPTER] [--out OUT]
                     [--json JSON_OUT] [--verbose] [--quiet] html
```

| 参数 | 说明 |
|---|---|
| `html` | 交付物 HTML（位置参数） |
| `--kb` | 知识库「原文」目录，或某一章的 .md；留空则按包结构自动定位（`kb/` 下只有一本时才自动选） |
| `--chapter` | 只校验某一章（章号前缀，如 `21`）；**留空则加载整库**，跨章交付物不必逐章切换 |
| `--out` | 报告输出路径，默认写到交付物同目录 |
| `--json` | 另存机器可读 JSON |
| `--verbose` | 展开「原文」级明细 |
| `--quiet` | 不打印控制台摘要 |

### pdf2kb.py

```text
usage: pdf2kb.py probe   <pdf> [--show-lines N] [--chapters FILE]
       pdf2kb.py extract <pdf> --out OUT [--title TITLE] [--tidy]
                                [--chapters FILE] [--ligature-fixes FILE]
                                [--strip-running-head] [--page-images DIR] [--dpi N]
```

| 参数 | 说明 |
|---|---|
| `probe --show-lines N` | 额外打印前 N 个低文字页的逐行内容 |
| `extract --out` | 知识库输出目录（必填） |
| `--title` | 库标题，默认取目录名 |
| `--tidy` | 只整理空白（去行尾空格、行内多空格压成一个），不改任何字符 |
| `--chapters` | 章节清单文件，每行 `起始书内页<TAB>标题`；PDF 没有书签时用它切章，`@` 开头为正文后的独立片段 |
| `--ligature-fixes` | 连字修正白名单文件，每行 `坏 -> 好` |
| `--strip-running-head` | 剥离跨页重复的页眉页脚行（默认保留） |
| `--page-images` / `--dpi` | 导出页面图片供视觉核对，默认 150 dpi |

### 其余脚本

```bash
python tools/kb_index.py --kb "kb/书名"                         # 重建索引
python tools/cite_check_selftest.py 交付物.html [--kb KB]        # 校验器自检
python tools/html2pdf.py 输入.html 输出.pdf                     # HTML → PDF
python tools/make_portable.py --kb "kb/书名" --deploy D:/kb      # 打包并同步副本
python tools/make_portable.py --dist                            # 只打工具链，不含书籍原文
```

## 7. 目录结构

```text
教材知识库工具包/
├── tools/                        全部脚本
│   ├── pdf2kb.py                 书籍 PDF → Markdown（probe / extract）
│   ├── kb_index.py               重建 原文索引.md
│   ├── cite_check.py             引用校验
│   ├── cite_check_selftest.py    校验器自检
│   ├── html2pdf.py               HTML → PDF（调用本机浏览器）
│   └── make_portable.py          打包 / 同步副本
├── skills/textbook-kb-cite/      AI 技能（可选安装）
├── kb/放知识库在这里.md           入库说明；分发版不含书籍原文
├── 新书入库核对清单.md
├── README.md
├── LICENSE
└── .gitignore
```

入库后的知识库结构：

```text
kb/<书名>/
├── 00-使用说明与版本信息.md      标记约定、书写约定、入库与校验流程
├── 原文索引.md                  入口：主题 / 章 → 文件 + 页码
├── _索引补充.md                  库专属附录：条目级细目、待办、交付物登记（可选）
├── _章节目录.txt                 章节清单：PDF 无书签时用它切章（可选，一旦有就是切章依据）
├── _连字修正白名单.txt           每行一条 `坏 -> 好`（可选）
└── 原文/                        逐字原文，唯一事实来源
    ├── _toc.md                  目录与页码映射（含偏移量）
    └── NN-章名.md               内嵌 <!-- pdf=42 book=21 --> 锚点
```

`原文/` 是脚本产物，手工编辑会被下一次抽取覆盖，并破坏「逐字保真」的可验证性。
`原文索引.md` 同理，由 `kb_index.py` 生成；要改内容须改脚本中的模板。

## 8. 常见问题

### 8.1 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `未能从交付物中抽取任何内容单元` | 交付物不符合 §4 的结构约定 | 按 §4 改写，或查看 `tools/cite_check.py` 顶部的 class 说明 |
| `抽到 N 个单元，却没有一条可校验的子句` | 单元内只有标题、栏目名这类极短文本 | 确认正文格 `cell` 内确实写了内容 |
| `未传 --kb，且未能按包结构自动定位到知识库` | `kb/` 下没有 `<书名>/原文/` 结构 | 放到 `kb/<书名>/原文/`，或显式传 `--kb` |
| `包内 kb/ 下有 N 个知识库，无法确定用哪个` | 多本共存，工具不做猜测 | 用 `--kb` 指定其中一本 |
| `该库可用章号：…` | 用 `--chapter` 指定的章号在该库不存在 | 按列出的章号改正，或去掉 `--chapter` 改为加载整库 |
| `ModuleNotFoundError: pymupdf` | 未安装入库依赖 | `pip install pymupdf`（仅入库需要） |

### 8.2 FAQ

**能用于扫描版 PDF 吗？**
不能。需要 PDF 自带文字层；工具不含 OCR，须先用其他工具转换。

**PDF 没有内置书签，能入库吗？**
能，但要多一步：从印刷目录页把「章起始页 + 章名」抄成章节清单（`_章节目录.txt`），
用 `--chapters` 传给 `probe` 与 `extract`。否则脚本只能退回每 25 页机械切块，
切出来的文件无法用于按章溯源。做法见 [§3.2](#32-入库一本资料)。

**能保证内容的正确性吗？**
不能。校验结果只反映字面一致性，语义层面的偏差由人判断。

**只能用于医学教材吗？**
不是。任何有文字层的 PDF 都可以入库，包括国家标准、行业规范、法规、技术手册。
工具判断的是「交付物与所引原文是否一致」，不含任何学科相关的逻辑。

**为什么按 class 校验，而不是直接读全文？**
需要区分正文、页码标记、旁注三种来源，并按行归属页码。若把页眉、页脚、分组标题
一并按事实陈述校验，报告会充斥大量无需关注的内容。

**一本教材的页码偏移能用到另一本上吗？**
不能。偏移量绑定具体 PDF，实测同为「第 10 版」的两本书也不同：
《皮肤性病学》第 10 版为 21、《妇产科学》第 10 版为 23、《精神病学》第 9 版为 17。

**同一台机器能放多本教材吗？**
能，`kb/` 下每本一个子目录。多本共存时校验必须用 `--kb` 指定，工具不会静默挑一本。

**原文里搜长句为什么搜不到？**
原文保留了 PDF 的原始换行，跨页处会被页眉和图注打断。先用短关键词检索，
再按 `book` 锚点读上下文；`book` 即书上印刷页码，反推物理页为 `book + 偏移量`。

## 9. 已知限制

- 只比对字面，不做语义判断；用词都在教材中而结论被改写的句子可能漏过
- 不含 OCR，扫描版 PDF 不可用
- 表格被压平成普通文本行（影响有限）
- 插图本身不抽取，只保留图注
- 存在整页插图页，跨页条目会绕过该页续排；标注页码范围前须确认该页有无正文
- 连字断裂修正依赖人工确认的白名单，不做自动合并（`of lesions` 这类正常词界
  会被误合并成 `oflisions`，且是静默发生）
- PDF 无内置书签时，章边界来自人工整理的章节清单；清单本身就是切章依据，
  抄错一处就会让那一章的页码区间整体错位，抄完必须对照目录页与章首页核两遍
