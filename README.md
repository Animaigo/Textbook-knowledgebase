# 教材知识库工具包

把 OCR 过的教科书电子文件转成 Markdown 并建立索引，让 AI 能按书上页码读原文、引原句。

![Python 3.9+](https://img.shields.io/badge/Python-3.9%2B-blue?style=flat-square)
![校验链 仅标准库](https://img.shields.io/badge/%E6%A0%A1%E9%AA%8C%E9%93%BE-%E4%BB%85%E6%A0%87%E5%87%86%E5%BA%93-lightgrey?style=flat-square)
![License MIT](https://img.shields.io/badge/License-MIT-green?style=flat-square)

**本包只含工具，不含任何书籍正文。** 要入库哪本书，自备哪本书的 PDF。

---

## 0. 说明

工具做的事只有一件：把一份 PDF 变成「可逐页溯源的 Markdown 原文」，再让 AI 基于它写作，
并在交付前逐句回查。

适用的是这类场景：

- 「这句话书上到底有没有？在第几页？」—— AI 写的内容逐句回查原文，无出处、夹带编造、页码标错都会单独列出来
- 「这道题对应书上的哪段原文？」—— 按主题或章检索索引，直接读到原句
- 需要大量引用和背诵的书尤其合适：定义、分类、条文这类内容，措辞本身就是考点

装上配套技能后，在 AI 里说一句「按照教科书…」即可触发，自动走完
「读原文 → 写作时标页码 → 跑校验」，拿到的引用都带书上页码。
不装技能也能用，同样的功能都有命令行入口。

工具的能力边界：

- 校验的是**字面一致性** —— 输出的文字是不是课本原文，不保证输出的知识正确与否
- **不含 OCR**。只有自带文字层的 PDF 能入库，扫描件要先用别的工具转；转出来的文字层质量差，入库结果同样不可靠
- 不参与内容创作，也不改写原文。原文一个字不动，写作由 AI 或人完成

不限学科。教材、国家标准、行业规范、法规、技术手册都能入库，只要 PDF 自带文字层。

## 1. 如何使用

下面按上手的顺序排。前三步是你的活：解压、跑一次示例、装技能。后面三件事 —— 入库、写作、校验 ——
装上技能后都能用一句话交给 AI，你只在两处拍板：入库时确认页码映射，交付前看校验结论。

### 1.1 解压到固定位置

解压后是一个 `教材知识库工具包/` 目录，把它放到长期不变的位置，例如 `D:\教材知识库\`。

```text
教材知识库工具包/
├── demo/          自带示例语料，用来跑通第一次校验
├── tools/         全部脚本
├── skills/        AI 技能，复制到 AI 的技能目录后生效
├── kb/            知识库放这里，每本书一个子目录
└── README.md
```

不要放在临时目录或随会话变动的工程目录：位置一飘，各处引用都要重新指路。
换盘符、换目录、换电脑都不影响使用 —— 脚本靠显式参数定位文件，包内没有任何写死的路径。

### 1.2 跑通自带示例

包内带了一份示例语料，不需要准备任何东西。解压后进入包目录
（Windows 可在文件夹地址栏敲 `cmd` 回车），运行：

```bash
python tools/cite_check.py demo/试跑.html --kb demo/原文
```

输出：

```text
知识库：demo（p.1–3，3 页，1 个文件）
交付物：试跑.html　单元 6 个，子句 3 条
------------------------------------------------------------
  ✗ 无出处（教材未见，且未声明为归纳）                     1  ███████████
  ✓ 原文（字面命中教材）                            2  ██████████████████████
------------------------------------------------------------
  ⚠ 需处理 1 条（无出处 1 + 含未见片段 0 + 页码错 0）
```

「无出处 1」是示例里故意埋的：一句编造的话，工具把它挑出来了。
报告写到交付物同目录，可以直接打开，看一条「必须处理」长什么样。

这一步只确认环境能跑。加引用校验只用 Python 标准库，不需要装任何依赖。

> [!NOTE]
> Windows 上敲 `python` 若弹出应用商店，说明系统里只有占位别名。
> 去 python.org 装正式版，之后用 `py -3 --version` 验证。

### 1.3 安装 AI 技能

把 `skills/textbook-kb-cite/` 整个目录复制到 AI 的技能目录：

| 环境 | 放到哪 |
|---|---|
| Windows | `C:\Users\<你的用户名>\.workbuddy\skills\` |
| macOS / Linux | `~/.workbuddy/skills/` |

复制完新开一个会话，让 AI 重新扫描技能目录。

用的是 Claude Code、Cursor 这类没有技能目录的工具？把 `skills/textbook-kb-cite/SKILL.md`
直接发给它读一遍，效果一样 —— 它本质是一份写给 AI 看的操作说明。

**这一步不是可选的。** 交付物是有特定 class 的 HTML（见 [1.7](#1-如何使用)），
正常做法是让 AI 写而不是手写。不装技能，AI 不知道要按什么结构写、页码标在哪，
产出会被校验器判「抽到 0 个内容单元」直接报错退出。

### 1.4 把自己的书入库

前提是 PDF 自带文字层。扫描件要先用别的工具转成带文字层的 PDF —— 本工具不含 OCR。

**装了技能的话，入库交给 AI 做。** 把文件路径给它，说一句：

> 把 `D:/书/内科学.pdf` 入库

它会跑完三步 —— 诊断（只读不落盘）→ 抽取 → 建索引 —— 然后汇报：文字层有没有、
页码偏移量与置信度、切章方案、连字可疑清单、库建在哪。判读标准在
[`新书入库核对清单.md`](新书入库核对清单.md)，拿不准的它会来问你。

**唯一需要你拍板的是页码偏移**：判错会让全书页码系统性偏移，而校验报告不会提示 ——
它只会安静地按错页码去比对。它报出偏移量后，你翻到 PDF 里任意一两个正文页，
对一下页脚印的页码对不对，就够。

**自己跑命令**也行，三步：

```bash
python tools/pdf2kb.py probe "D:/书/内科学.pdf"                    # 诊断，只读，可反复跑
python tools/pdf2kb.py extract "D:/书/内科学.pdf" --out "kb/内科学/原文" --tidy
python tools/kb_index.py --kb "kb/内科学"
```

`--out` 必须落在 `kb/<书名>/原文`，自动定位依赖这个结构。
入库需要 `pymupdf`：`pip install pymupdf`。
probe 输出的判读标准（置信度分档、不一致的页怎么归类、连字清单怎么筛）逐条列在核对清单里。

**PDF 没有内置书签时**，章边界只能靠一份人工清单：从印刷目录页把「章起始页 + 章名」抄下来，
每行 `起始书内页<TAB>标题`，`#` 开头是注释，用 `--chapters` 交给 `probe` 和 `extract`
（目录页交给 AI 也能整理成清单，但核两遍这一步不能省。）

```text
# kb/内科学/_章节目录.txt
1	第一章 绪论
10	第二章 呼吸系统疾病
330	@后置材料（推荐阅读与索引）    ← @ 开头 = 正文之后的独立片段
```

```bash
python tools/pdf2kb.py probe   "D:/书/内科学.pdf" --chapters "kb/内科学/_章节目录.txt"
python tools/pdf2kb.py extract "D:/书/内科学.pdf" --out "kb/内科学/原文" --tidy \
    --chapters "kb/内科学/_章节目录.txt"
```

这份清单是切章依据、会留在库里，不是用完即弃的临时文件；抄完核两遍：逐条对目录页，
再抽查各章 PDF 首页是不是该章开头。抄错一处，那一章的页码区间就会整体错位。

### 1.5 让 AI 按教科书写东西

技能装好、书也入库之后，用自然语言触发即可，例如：

- 「按照《内科学》教科书，整理××的分型，每句标注页码」
- 「书上关于××的原文是怎么写的」
- 「这份笔记里的内容，教科书上都有依据吗」
- 「帮我核对这份交付物的页码」

句子里出现「按照教科书」「按教材写」「依据教材」「教材原文」「引用校验」「核对页码」
这类说法时会自动加载技能。之后 AI 的固定动作为：

1. 读 `原文索引.md` 定位到章
2. 在 `原文/NN-*.md` 里检索原句
3. 写作，每段标注书上印刷页码
4. 交付前跑一遍引用校验，把「无出处」「含未见片段」处理掉再交

前提是 AI 找得到库。库在包内的 `kb/<书名>/原文/`；多本共存时在提问里指明书名，
或直接给路径 —— 工具不做猜测。生成的文件要符合什么结构，见 [1.7](#1-如何使用)。

### 1.6 交付前跑校验

```bash
python tools/cite_check.py 交付物.html
```

`--kb` 可以省略：`kb/` 下只有一本时自动定位。多本共存时必须用
`--kb kb/<书名>/原文` 指明。

每条子句按对原文的贴合程度归入九档，按处理方式分三类。

**必须处理** —— 摘要里的「需处理 N 条」就是这三类之和

| 判定 | 含义 |
|---|---|
| ✗ 无出处 | 整句在所引原文里找不到，且未声明为归纳 |
| ✗ 含未见片段 | 句子有原文作底，但夹进了原文没有的内容 |
| ⚠ 异地 | 内容出自原文，页码标错了；改页码即可 |

**需人工确认**

| 判定 | 含义 |
|---|---|
| ⚠ 改写·接近 | 措辞略有出入，大概率等价 |
| ⚠ 改写·部分 | 重合度偏低，可能是转述，也可能是混写 |

**通过**

| 判定 | 含义 |
|---|---|
| ✓ 原文 | 字面命中所引资料的该页 |
| ◇ 重组 | 每个信息元都在原文里，只是排列不同 |
| ◇ 声明留白 | 交付物明说「教材未述」，找不到正合预期 |
| ◇ 归纳 | 声明为归纳，或位于说明区，无出处属预期 |

摘要末行是「✓ 未检出『教材未见』的内容」时，必须处理项为零。

**唯一的门槛：报告里出现「无出处」或「含未见片段」，不要交付。**

其余参数（展开明细、另存 JSON、只校验某一章）见 [4.2](#4-命令行参考)。

### 1.7 交付物结构约定

**用技能写作时不必关心这节** —— AI 会按下面的约定生成。它写给两种情况：自己手写交付物，
或者想核对 AI 产出的结构对不对。

校验器按 class 识别内容，不是通用的 HTML 文本提取器 —— 只有认得出结构，
才能区分正文、页码标记与旁注。最小可用结构：

```html
<div class="row">
  <span class="pg">p.21</span>
  <div class="name">术语名</div>
  <div class="cell">照抄原文的一句</div>
  <div class="cell">这句是编的：所有条目都会在三天内自行消失</div>
</div>
```

| class | 放什么 | 是否校验 |
|---|---|---|
| `row` | 一行 | 容器，不校验 |
| `pg` | 页码标记，如 `<span class="pg">p.21</span>` | 不校验，决定这一行的页码 |
| `cell` | 行内正文格 | 校验，须有原文支撑 |
| `name` | 名称列（术语名、条目名） | 校验；其中外文名单独校验 |
| `sub` / `sub-grid` | 子表格（分型、分级等） | 校验 |
| `sx` / `sxh` / `v` | 条目卡容器 / 标题 / 内容 | 校验 |
| `ov-grid` | 总览区 | 校验 |
| `note` | 内嵌旁注 | 软性，无出处不算错 |
| `na` | 「教材未述」留白标记 | 软性，找不到才是对的 |
| `disc-grid` | 辨析区（内容来自多页） | 软性，不锁页码 |
| `layer` / `foot` / `gnote` / `ghead` / `schead` | 层次带 / 页脚 / 分组说明 / 分组标题 / 节标题 | 软性 |

示例句取自一本医学教材。换成法学、工程、金融的资料时，class 用法完全一样 ——
要区分的始终是「正文 / 页码标记 / 旁注」这三种来源，与资料属于哪个学科无关。

两类位置的区别是实质性的：软性位置（旁注、页脚、分组标题）允许是编者自己的话，
不会因为在书里找不到就被判错；其余位置要求字面有原文支撑，找不到就报出来。
另有一条例外：文字中自称「教材原文 / 教材明言」或标了 `p.xx` 的，无论放在哪都严格校验。

> [!WARNING]
> 交付物若是普通 HTML（`<h1>`/`<p>` 不带上述 class），校验器会抽出 0 个内容单元并
> **直接报错退出**，不会输出一份写着「未检出教材未见的内容」的报告 ——
> 没校验过就不会给通过结论。

## 2. 注意事项

### 2.1 页码映射绑定这一份 PDF

`书上页码 = PDF 物理页 − 偏移量`。偏移量随印次、版本变化 —— 实测几本同为「第 10 版」的教材，
偏移分别是 21、23、17。**换 PDF（哪怕同一版次另下一份）就必须重跑 `probe`，不要沿用任何现成数字。**

### 2.2 `原文/` 与 `原文索引.md` 是脚本产物

手工编辑会被下一次抽取或建索引覆盖，也会破坏「逐字保真」的可验证性。
库专属内容（条目细目、待办、交付物登记）写到 `_索引补充.md`。
改脚本生成的文件，下次重建就白改了。

### 2.3 章节清单进了库就是切章依据

无书签的 PDF 靠 `_章节目录.txt` 切章。改这份清单等于改章边界 —— 改完要重跑 `extract`
和 `kb_index`，并重新抽查章首页；只改清单不重跑，索引里的章号与页码区间还是旧的。

### 2.4 多本共存时工具不猜

`kb/` 下有多本时，`cite_check.py` 会报错并列出候选，必须用 `--kb` 指定。
猜错一本的后果是拿着 A 书的原文去校验 B 书的内容，而报告看起来完全正常。

### 2.5 已知限制

- 只比对字面，不做语义判断；用词都在书里而结论被改写的句子可能漏过
- 不含 OCR，扫描版 PDF 不可用
- 表格被压平成普通文本行（影响有限）；插图本身不抽取，只保留图注
- 原文保留 PDF 的原始换行，跨页处会被页眉和图注打断 —— 检索时用短关键词，
  再按 `book` 锚点看上下文（`book` 是书上印刷页码，反推物理页是 `book + 偏移量`）
- 书里若有整页插图页，跨页的条目会绕过它续排 —— 页码对不上时，先确认那一页有没有正文
- 连字断裂的修正靠人工确认的白名单，不做自动合并（细节见 `新书入库核对清单.md`）

## 3. 故障排查

下面这些多数是 AI 跑校验时冒出来的，把它的报错原样贴过来就能对上：

| 现象 | 原因 | 处理 |
|---|---|---|
| `未能从交付物中抽取任何内容单元` | 交付物不符合 1.7 的结构约定 | 按 1.7 改写，或看 `tools/cite_check.py` 顶部的 class 说明 |
| `抽到 N 个单元，却没有一条可校验的子句` | 单元里只有标题、栏目名这类极短文本 | 确认正文格 `cell` 里确实写了内容 |
| `未传 --kb，且未能按包结构自动定位到知识库` | `kb/` 下没有 `<书名>/原文/` 结构 | 放到 `kb/<书名>/原文/`，或显式传 `--kb` |
| `包内 kb/ 下有 N 个知识库，无法确定用哪个` | 多本共存，工具不做猜测 | 用 `--kb` 指定其中一本 |
| `该库可用章号：…` | `--chapter` 指定的章号在该库里不存在 | 按列出的章号改正，或去掉 `--chapter` 加载整库 |
| `ModuleNotFoundError: pymupdf` | 没装入库依赖 | `pip install pymupdf`（只有入库需要） |

怀疑校验器本身坏了（改过脚本、换过机器），跑一次自检：

```bash
python tools/cite_check_selftest.py 交付物.html
```

它验五件事：交付物与知识库跨盘符时报告仍能生成；`kb/` 下有多本时不会乱猜用哪本；
交付物结构不匹配时报错退出，而不是假装通过；基底交付物本身没有必须处理项；
以及能不能检出三类历史上真实发生过的错误。

末行出现 `结果：检出 3/3` 加「校验器工作正常」，即工具正常。

> [!IMPORTANT]
> 最后一项（检出能力）的测试点位是按某一本特定资料写死的。换成你自己的资料后，
> 基底交付物里没有那些点位，这一步会跳过、报「检出能力未验证」并以非 0 退出 ——
> 这是预期行为，不代表工具坏了。要让它对新资料也生效，得按新资料改写
> `cite_check_selftest.py` 里的测试点位。

**扫描版 PDF 能用吗？** 不能。需要 PDF 自带文字层，工具不含 OCR。

**能保证内容的正确性吗？** 不能。校验结果只反映字面一致性，语义层面的偏差由人判断。

**同一台机器能放多本资料吗？** 能，`kb/` 下每本一个子目录，多本共存时校验带 `--kb`。

## 4. 命令行参考

### 4.1 脚本与依赖

| 脚本 | 依赖 | 什么时候用 |
|---|---|---|
| `cite_check.py` | Python ≥3.9，仅标准库 | 每次交付前，日常主力 |
| `kb_index.py` | 仅标准库 | 入库后 / 改了原文后 |
| `pdf2kb.py` | `pymupdf` | 只有入库需要 |
| `html2pdf.py` | 本机 Edge 或 Chrome | 想把成果导出成 PDF 时 |
| `cite_check_selftest.py` | 仅标准库 | 怀疑校验器本身出问题时 |
| `make_portable.py` | 仅标准库 | 打包、同步副本 |

也就是：**只跑校验不用装任何东西；要入库自己的书，才需要 `pip install pymupdf`。**

### 4.2 cite_check.py

```text
usage: cite_check.py [-h] [--kb KB] [--chapter CHAPTER] [--out OUT]
                     [--json JSON_OUT] [--verbose] [--quiet] html
```

| 参数 | 说明 |
|---|---|
| `html` | 交付物 HTML（位置参数） |
| `--kb` | 知识库「原文」目录，或某一章的 .md；留空则按包结构自动定位（`kb/` 下只有一本时自动选） |
| `--chapter` | 只校验某一章（章号前缀，如 `21`）；**留空则加载整库**，跨章交付物不必逐章切换。整库模式下，别的章里恰好相同的字句可能把本页有支撑的内容判成「异地」，出现可疑的「异地」时用这个参数复跑单章 |
| `--out` | 报告输出路径，默认写到交付物同目录 |
| `--json` | 另存机器可读 JSON |
| `--verbose` | 展开「原文」级明细 |
| `--quiet` | 不打印控制台摘要 |

### 4.3 pdf2kb.py

```text
usage: pdf2kb.py probe   <pdf> [--show-lines N] [--chapters FILE]
       pdf2kb.py extract <pdf> --out OUT [--title TITLE] [--tidy]
                                [--chapters FILE] [--ligature-fixes FILE]
                                [--strip-running-head] [--page-images DIR] [--dpi N]
```

| 参数 | 说明 |
|---|---|
| `probe --show-lines N` | 额外打印前 N 个低文字页的逐行内容 |
| `extract --out` | 知识库输出目录（必填） |
| `--title` | 库标题，默认取目录名 |
| `--tidy` | 只整理空白（去行尾空格、行内多空格压成一个），不改任何字符 |
| `--chapters` | 章节清单，每行 `起始书内页<TAB>标题`；PDF 无书签时用它切章，`@` 开头为正文后的独立片段 |
| `--ligature-fixes` | 连字修正白名单，每行 `坏 -> 好` |
| `--strip-running-head` | 剥离跨页重复的页眉页脚行（默认保留） |
| `--page-images` / `--dpi` | 导出页面图片供视觉核对，默认 150 dpi |

> [!NOTE]
> `--strip-running-head` 默认关闭，建议保持关闭：章的起始页常以「第四章 XXX」占据页眉位置，
> 剥离页眉会连章标题一起删掉。确需使用时，事后必须核对章标题还在不在。

### 4.4 其余脚本

```bash
python tools/kb_index.py --kb "kb/书名"                          # 重建索引
python tools/cite_check_selftest.py 交付物.html [--kb KB]         # 校验器自检
python tools/html2pdf.py 输入.html 输出.pdf                      # HTML → PDF
python tools/make_portable.py --kb "kb/书名" --deploy D:/kb       # 打包并同步副本
python tools/make_portable.py --dist                             # 只打工具链，不含书籍原文
```

入库后的知识库长这样：

```text
kb/<书名>/
├── 00-使用说明与版本信息.md      标记约定、书写约定、入库与校验流程
├── 原文索引.md                   入口：主题 / 章 → 文件 + 页码
├── _索引补充.md                  库专属附录：条目级细目、待办、交付物登记（可选）
├── _章节目录.txt                 章节清单：PDF 无书签时用它切章（可选，一旦有就是切章依据）
├── _连字修正白名单.txt           每行一条 `坏 -> 好`（可选）
└── 原文/                         逐字原文，唯一事实来源
    ├── _toc.md                   目录与页码映射（含偏移量）
    └── NN-章名.md                内嵌 <!-- pdf=42 book=21 --> 锚点
```
