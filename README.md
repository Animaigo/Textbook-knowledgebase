# 教材知识库工具包

让 AI 写的「严格依据某本书」的内容，逐句回查原文 —— 哪句书里根本没有、哪句页码标错了，一条条列出来。

**本包只含工具，不含任何书籍正文。** 要用它，你得自备一份带文字层的 PDF，按 [§3](#3-入库一本资料) 入库。
原因见 [§12](#12-版权与许可)。

## 它能抓什么

```
结节为实质性、深在性、可触诊的皮损，直径一般大于 1cm。
```

前半句书里有，后半句没有。这类句子和原文重合度能到七成，人眼逐字核对时极容易放过。

工具用滑动窗口取最长连续命中，把没有原文支撑的片段单独标出来，判为「含未见片段」。
它只比字面，不做语义判断 —— 用词都能在书里找到、但结论被改写的句子，会落在「改写」档
交给你人工确认，而不是直接判错。它衡量的是「这段文字有没有偏离所引原文」，
不是「内容本身对不对」。

不限学科。教材、国家标准、行业规范、法规、技术手册都能入库，只要 PDF 自带文字层。

## 30 秒跑通（不用准备任何资料）

包里带了一份示例。解压后，在包目录里打开命令行（Windows 可在文件夹地址栏敲 `cmd` 回车），运行：

```bash
python tools/cite_check.py demo/试跑.html --kb demo/原文
```

应该看到：

```text
知识库：demo（p.1–3，3 页，1 个文件）
交付物：试跑.html　单元 6 个，子句 3 条
------------------------------------------------------------
  ✗ 无出处（教材未见，且未声明为归纳）                     1
  ✓ 原文（字面命中教材）                            2
------------------------------------------------------------
  ⚠ 需处理 1 条（无出处 1 + 含未见片段 0 + 页码错 0）
```

「无出处 1」是故意留的：示例交付物里藏了一句编的话，工具把它挑出来了。

这一步只为确认环境能跑，不需要装任何依赖 —— 校验链只用 Python 标准库。
跑出来的报告在 `demo/试跑-引用校验报告.md`，可以打开看看长什么样。

## 1. 装什么

| 脚本 | 依赖 | 什么时候用 |
|---|---|---|
| `cite_check.py` | Python ≥3.9，仅标准库 | 每次交付前，日常主力 |
| `kb_index.py` | 仅标准库 | 入库后 / 改了原文后 |
| `pdf2kb.py` | `pymupdf` | 只有入库需要 |
| `html2pdf.py` | 本机 Edge 或 Chrome | 想把成果导出成 PDF 时 |
| `cite_check_selftest.py` | 仅标准库 | 怀疑校验器本身出问题时 |
| `make_portable.py` | 仅标准库 | 打包、同步副本 |

也就是：**只跑校验不用装任何东西；要入库自己的书，才需要 `pip install pymupdf`。**

> [!NOTE]
> Windows 上敲 `python` 若弹出应用商店，说明系统里只有占位别名。
> 去 python.org 装正式版，之后用 `py -3 --version` 验证。

## 2. 放在哪

解压到**长期不变的位置**，例如 `D:\教材知识库\`。

`tools/` 和 `kb/` 是兄弟目录，`cite_check.py` 靠自身位置推断库在哪，
所以不用配置任何路径、也不用传 `--kb`，换盘符换目录都有效。

唯一要求：别放在随会话变动的临时目录里。位置一飘，各处引用都要重新指路。

## 3. 入库一本资料

把一份 PDF 变成可逐页溯源的原文。三步：诊断 → 抽取 → 建索引。

### 3.1 先诊断（只读，不产生任何文件）

```bash
python tools/pdf2kb.py probe "D:/书/你的资料.pdf"
```

`probe` 只诊断、不落盘，可以放心反复跑。它输出四项，**每一项都要看**。

### 3.2 四项诊断怎么读

**① 文字层**

```text
判定：含有效文字层，可直接抽取原文（零 OCR 误差）
```

看到这行才能继续。平均每页一千余字符属正常。若显示「无文字层」或每页只有几十字符，
说明是扫描版 —— 本工具不含 OCR，得先用别的工具转成带文字层的 PDF。

**② 页码偏移**（决定全书页码，最需要盯的一项）

```text
页码映射：书内页码 = 物理页 − 21　｜　置信度 91%
```

意思是：这份 PDF 的第 42 个物理页，印在书上是第 21 页。偏移量绑定**这一份 PDF**，
换印次、换版本就作废。

| 置信度 | 怎么办 |
|---|---|
| ≥ 85% | 可以继续，但仍要扫一眼「不一致的页」列表 |
| 60–85% | 必须人工抽查：任选 3 个正文页，跟 PDF 肉眼对一遍 |
| < 60% | 停手，这个映射不可信 |

「不一致的页」若只含封面、版权页、目录、序言这类前置页，属正常；夹了正文页码就要查清原因。
**这里判错会让全书页码系统性偏移，而校验报告不会提示你。**

**③ 切章方案**

```text
切章方案：按书签第 2 级（共 29 章）
```

按书签切章是最好的情况。另外两种都要先处理，别在错误边界上继续：

- `⚠ 未识别出章级目录，将退回按 25 页机械切块` —— 书签里没有「第X章」条目
- `内置书签目录：0 条　⚠ 无目录` —— 这份 PDF 根本没有书签

两种情况都能靠**章节清单**解决：从**印刷目录页**把「章起始页 + 章名」抄成一份文本，
每行 `起始书内页<TAB>标题`，`#` 开头是注释，用 `--chapters` 传进去：

```text
# kb/你的书名/_章节目录.txt
1	第一章 绪论
10	第二章 精神障碍的症状学
330	@后置材料（推荐阅读与中英文名词对照索引）    ← @ 开头 = 正文后的独立片段
```

```bash
python tools/pdf2kb.py probe   "D:/书/你的资料.pdf" --chapters "kb/你的书名/_章节目录.txt"
python tools/pdf2kb.py extract "D:/书/你的资料.pdf" --out "kb/你的书名/原文" --tidy \
    --chapters "kb/你的书名/_章节目录.txt"
```

清单要核两遍：逐条对照目录页，再抽查各章 PDF 首页是不是该章开头。
清单放进知识库留档 —— 它同时是切章依据，不是临时文件。

**④ 连字断裂**

```text
连字断裂可疑（如 `f issure`）：29 种 / 75 处
          示例：`f ibers`×8、`immunof luorescence`×4
```

这是**可疑清单不是错误清单**，得逐条判断：`f issure` 是抽取时把 fissure 拆断了，该修；
`of lesions`、`of interest` 是正常词界，不能修。判不准就别写进白名单。

### 3.3 抽取并建索引

四项都过了再执行：

```bash
# 抽取。--out 是输出目录，跟 cite_check 的 --kb（输入）不是一回事
python tools/pdf2kb.py extract "D:/书/你的资料.pdf" --out "kb/你的书名/原文" --tidy

# 有连字白名单时追加
python tools/pdf2kb.py extract "D:/书/你的资料.pdf" --out "kb/你的书名/原文" --tidy \
    --ligature-fixes "kb/你的书名/_连字修正白名单.txt"

# 重建索引，生成「原文索引.md」
python tools/kb_index.py --kb "kb/你的书名"
```

`--out` 必须落在 `kb/<书名>/原文`，自动定位依赖这个结构。

> [!NOTE]
> `--strip-running-head` 默认关闭，建议保持关闭：章的起始页常以「第四章 XXX」占据页眉位置，
> 剥离页眉会连章标题一起删掉。确需使用时，事后必须核对章标题还在不在。

诊断数字的完整判读范围与停手条件见 [`新书入库核对清单.md`](新书入库核对清单.md)。

### 3.4 装上 AI 技能（强烈建议）

把 `skills/textbook-kb-cite/` 整个目录复制到 AI 的技能目录：

| 环境 | 放到哪 |
|---|---|
| Windows | `C:\Users\<你的用户名>\.workbuddy\skills\` |
| macOS / Linux | `~/.workbuddy/skills/` |

装上之后，提到「按教材写」「教材原文」「引用校验」，AI 会自动走完
「读原文 → 写作时标页码 → 跑校验」整个流程，不用你每次重述约定。

用的是其他 AI 工具（Claude Code、Cursor 之类）？把 `skills/textbook-kb-cite/SKILL.md`
直接丢给 AI 读一遍就行，效果一样 —— 它本质就是一份写给 AI 看的操作说明。

**这一步不是可选的。** 交付物是带特定 class 的 HTML（见 [§6](#6-交付物结构约定)），
正常人的做法是让 AI 写，而不是手写。不装技能，AI 不知道要按什么结构写，
产出会被校验器判「抽到 0 个内容单元」直接报错退出。技能里路径写法是「自动定位优先、
显式路径兜底」，换位置不用改。

## 4. 日常用法

库建好之后，日常就是这个循环：

1. 让 AI 按库写内容（装过技能的话说一句「按这个库写 XX，每句标页码」即可）
2. 跑校验：
   ```bash
   python tools/cite_check.py 交付物.html
   ```
   `--kb` 可以省略：`kb/` 下只有一本时脚本自动定位。
3. 报告里出现「无出处」或「含未见片段」，退回修改，改完再跑一遍

`kb/` 下有多本时会明确报错并列出候选，用 `--kb kb/<库名>/原文` 指定即可 —— 工具不会替你猜。

## 5. 报告判读

每条子句归入九档之一，按处理方式分三类。

**必须处理** —— 摘要里「需处理 N 条」就是这三类之和

| 判定 | 含义 |
|---|---|
| ✗ 无出处 | 整句在所引原文里找不到，且未声明为归纳 |
| ✗ 含未见片段 | 句子有原文作底，但夹进了原文没有的内容 |
| ⚠ 异地 | 内容出自原文，页码标错了；改页码即可 |

**需人工确认**

| 判定 | 含义 |
|---|---|
| ⚠ 改写·接近 | 措辞略有出入，大概率等价 |
| ⚠ 改写·部分 | 重合度偏低，可能是转述，也可能是混写 |

**通过**

| 判定 | 含义 |
|---|---|
| ✓ 原文 | 字面命中所引资料的该页 |
| ◇ 重组 | 每个信息元都在原文里，只是排列不同 |
| ◇ 声明留白 | 交付物明说「教材未述」，找不到正合预期 |
| ◇ 归纳 | 声明为归纳，或位于说明区，无出处属预期 |

摘要末行是「✓ 未检出『教材未见』的内容」时，必须处理项为零。

```bash
python tools/cite_check.py 交付物.html --verbose          # 展开「原文」级明细
python tools/cite_check.py 交付物.html --json 结果.json   # 另存机器可读结果
python tools/cite_check.py 交付物.html --chapter 21       # 只校验第 21 章
```

**交付前唯一的门槛：报告里出现「无出处」或「含未见片段」，不要交付。**

## 6. 交付物结构约定

校验器按 class 识别内容，不是通用的 HTML 文本提取器 —— 只有认得出结构，
才能区分正文、页码标记与旁注。最小可用结构：

```html
<div class="row">
  <span class="pg">p.21</span>
  <div class="name">斑疹</div>
  <div class="cell">皮肤黏膜的局限性颜色改变，直径 ≤1cm</div>
  <div class="cell">这句是编的：所有皮损都会在三天内自行消退</div>
</div>
```

| class | 放什么 | 是否校验 |
|---|---|---|
| `row` | 一行 | 容器，不校验 |
| `pg` | 页码标记，如 `<span class="pg">p.21</span>` | 不校验，决定这一行的页码 |
| `cell` | 行内正文格 | 校验，须有原文支撑 |
| `name` | 名称列（术语名、条目名） | 校验；其中外文名单独校验 |
| `sub` / `sub-grid` | 子表格（分型、分级等） | 校验 |
| `sx` / `sxh` / `v` | 条目卡容器 / 标题 / 内容 | 校验 |
| `ov-grid` | 总览区 | 校验 |
| `note` | 内嵌旁注 | 软性，无出处不算错 |
| `na` | 「教材未述」留白标记 | 软性，找不到才是对的 |
| `disc-grid` | 辨析区（内容来自多页） | 软性，不锁页码 |
| `layer` / `foot` / `gnote` / `ghead` / `schead` | 层次带 / 页脚 / 分组说明 / 分组标题 / 节标题 | 软性 |

示例句取自一本皮肤科教材。换成法学、工程、金融的资料时，class 用法完全一样 ——
要区分的始终是「正文 / 页码标记 / 旁注」这三种来源，跟资料属于哪个学科无关。

两类位置的区别是实质性的：软性位置（旁注、页脚、分组标题）允许是编者自己的话，
不会因为在书里找不到就被判错；其余位置要求字面有原文支撑，找不到就报出来。
另有一条例外：文字中自称「教材原文 / 教材明言」或标了 `p.xx` 的，无论放在哪都严格校验。

> [!WARNING]
> 交付物若是普通 HTML（`<h1>`/`<p>` 不带上述 class），校验器会抽出 0 个内容单元并
> **直接报错退出**，不会输出一份写着「未检出教材未见的内容」的报告 ——
> 没校验过就不会给通过结论。

## 7. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `未能从交付物中抽取任何内容单元` | 交付物不符合 §6 的结构约定 | 按 §6 改写，或看 `tools/cite_check.py` 顶部的 class 说明 |
| `抽到 N 个单元，却没有一条可校验的子句` | 单元里只有标题、栏目名这类极短文本 | 确认正文格 `cell` 里确实写了内容 |
| `未传 --kb，且未能按包结构自动定位到知识库` | `kb/` 下没有 `<书名>/原文/` 结构 | 放到 `kb/<书名>/原文/`，或显式传 `--kb` |
| `包内 kb/ 下有 N 个知识库，无法确定用哪个` | 多本共存，工具不做猜测 | 用 `--kb` 指定其中一本 |
| `该库可用章号：…` | `--chapter` 指定的章号在该库里不存在 | 按列出的章号改正，或去掉 `--chapter` 加载整库 |
| `ModuleNotFoundError: pymupdf` | 没装入库依赖 | `pip install pymupdf`（只有入库需要） |

怀疑校验器本身坏了（比如改过脚本、换了机器），跑一次自检：

```bash
python tools/cite_check_selftest.py 交付物.html
```

它依次验证五件事：

| 步骤 | 验证内容 |
|---|---|
| 第 0 步 · 环境健壮性 | 交付物与知识库跨盘符时，报告仍能生成 |
| 第 0b 步 · 知识库定位 | 单本可定位、多本不猜测、空包不指定 |
| 第 0c 步 · 零单元守卫 | 结构不匹配时报错退出，而不是输出「通过」 |
| 第 1 步 · 基线 | 作为基底的交付物本身没有必须处理项 |
| 第 2 步 · 检出能力 | 植入三类历史上真实发生过的错误，要求逐条检出 |

末行出现 `结果：检出 3/3` 加「校验器工作正常」，即工具正常。

> [!IMPORTANT]
> 第 2 步的植入锚点写在 `cite_check_selftest.py` 的 `PLANTS` 里，针对《皮肤性病学》第 10 版。
> 基底交付物不含这些锚点时该步会跳过，脚本判「检出能力未验证」并以非 0 退出 ——
> 换书使用时得按新资料改写锚点，并用那份资料的交付物作基底。

## 8. 常见问题

**能用于扫描版 PDF 吗？**
不能。需要 PDF 自带文字层；工具不含 OCR，得先用别的工具转换。

**PDF 没有内置书签，能入库吗？**
能，但要多一步：从印刷目录页把「章起始页 + 章名」抄成章节清单（`_章节目录.txt`），
用 `--chapters` 传给 `probe` 和 `extract`。否则脚本只能退回每 25 页机械切块，
切出来的文件没法按章溯源。做法见 [§3.2](#32-四项诊断怎么读)。

**能保证内容的正确性吗？**
不能。校验结果只反映字面一致性，语义层面的偏差由人判断。

**只能用于医学教材吗？**
不是。任何带文字层的 PDF 都能入库，包括国家标准、行业规范、法规、技术手册。
工具判断的是「交付物与所引原文是否一致」，不含任何学科相关的逻辑。

**为什么按 class 校验，而不是直接读全文？**
需要区分正文、页码标记、旁注三种来源，并按行归属页码。要是把页眉、页脚、分组标题
一并当事实陈述校验，报告会被大量无需关注的内容淹没。

**一本书的页码偏移能用到另一本上吗？**
不能。偏移量绑定具体 PDF，实测同为「第 10 版」的书也不一样：
《皮肤性病学》第 10 版是 21、《妇产科学》第 10 版是 23、《精神病学》第 9 版是 17。

**同一台机器能放多本资料吗？**
能，`kb/` 下每本一个子目录。多本共存时校验必须用 `--kb` 指定，工具不会静默挑一本。

**原文里搜长句为什么搜不到？**
原文保留了 PDF 的原始换行，跨页处会被页眉和图注打断。先用短关键词检索，
再按 `book` 锚点读上下文；`book` 就是书上印刷页码，反推物理页是 `book + 偏移量`。

## 9. 命令行参考

```text
usage: cite_check.py [-h] [--kb KB] [--chapter CHAPTER] [--out OUT]
                     [--json JSON_OUT] [--verbose] [--quiet] html
```

| 参数 | 说明 |
|---|---|
| `html` | 交付物 HTML（位置参数） |
| `--kb` | 知识库「原文」目录，或某一章的 .md；留空则按包结构自动定位（`kb/` 下只有一本时自动选） |
| `--chapter` | 只校验某一章（章号前缀，如 `21`）；**留空则加载整库**，跨章交付物不必逐章切换 |
| `--out` | 报告输出路径，默认写到交付物同目录 |
| `--json` | 另存机器可读 JSON |
| `--verbose` | 展开「原文」级明细 |
| `--quiet` | 不打印控制台摘要 |

```text
usage: pdf2kb.py probe   <pdf> [--show-lines N] [--chapters FILE]
       pdf2kb.py extract <pdf> --out OUT [--title TITLE] [--tidy]
                                [--chapters FILE] [--ligature-fixes FILE]
                                [--strip-running-head] [--page-images DIR] [--dpi N]
```

| 参数 | 说明 |
|---|---|
| `probe --show-lines N` | 额外打印前 N 个低文字页的逐行内容 |
| `extract --out` | 知识库输出目录（必填） |
| `--title` | 库标题，默认取目录名 |
| `--tidy` | 只整理空白（去行尾空格、行内多空格压成一个），不改任何字符 |
| `--chapters` | 章节清单，每行 `起始书内页<TAB>标题`；PDF 无书签时用它切章，`@` 开头为正文后的独立片段 |
| `--ligature-fixes` | 连字修正白名单，每行 `坏 -> 好` |
| `--strip-running-head` | 剥离跨页重复的页眉页脚行（默认保留） |
| `--page-images` / `--dpi` | 导出页面图片供视觉核对，默认 150 dpi |

其余脚本：

```bash
python tools/kb_index.py --kb "kb/书名"                         # 重建索引
python tools/cite_check_selftest.py 交付物.html [--kb KB]        # 校验器自检
python tools/html2pdf.py 输入.html 输出.pdf                     # HTML → PDF
python tools/make_portable.py --kb "kb/书名" --deploy D:/kb      # 打包并同步副本
python tools/make_portable.py --dist                            # 只打工具链，不含书籍原文
```

```text
│   ├── cite_check_selftest.py    校验器自检
│   ├── html2pdf.py               HTML → PDF（调用本机浏览器）
│   └── make_portable.py          打包 / 同步副本
├── skills/textbook-kb-cite/      AI 技能（建议安装）

│   ├── 试跑.html
│   └── 原文/01-工具说明.md

├── README.md

```

入库后的知识库长这样：

```text
kb/<书名>/
├── 00-使用说明与版本信息.md      标记约定、书写约定、入库与校验流程
├── 原文索引.md                  入口：主题 / 章 → 文件 + 页码
├── _索引补充.md                  库专属附录：条目级细目、待办、交付物登记（可选）
├── _章节目录.txt                 章节清单：PDF 无书签时用它切章（可选，一旦有就是切章依据）
├── _连字修正白名单.txt           每行一条 `坏 -> 好`（可选）
└── 原文/                        逐字原文，唯一事实来源
    ├── _toc.md                  目录与页码映射（含偏移量）
    └── NN-章名.md               内嵌 <!-- pdf=42 book=21 --> 锚点
```

`原文/` 是脚本产物，手工编辑会被下一次抽取覆盖，并破坏「逐字保真」的可验证性。
`原文索引.md` 同理，由 `kb_index.py` 生成。

## 11. 已知限制

- 只比对字面，不做语义判断；用词都在书里而结论被改写的句子可能漏过
- 不含 OCR，扫描版 PDF 不可用
- 表格被压平成普通文本行（影响有限）
- 插图本身不抽取，只保留图注
- 资料存在整页插图页时，跨页条目会绕过该页续排；标页码前须确认该页有没有正文
- 连字断裂修正依赖人工确认的白名单，不做自动合并（`of lesions` 这类正常词界
  会被误合并成 `oflisions`，而且是静默发生的）
- PDF 无内置书签时，章边界来自人工整理的章节清单；清单本身就是切章依据，
  抄错一处就会让那一章的页码区间整体错位，抄完必须对照目录页与章首页核两遍
- 不传 `--chapter` 时加载整库：跨章交付物不必逐章切换，但别章的巧合字面串
  可能把本页已有支撑的内容判成「异地」，可疑时用 `--chapter` 复跑单章
